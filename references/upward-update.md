# 向上汇报指南

## 什么时候用
用户说"给老板汇报""跟领导同步进展""月度汇报""向上汇报一下"。

和周报的区别：周报是定期的面面俱到，向上汇报是**针对一个具体项目/事，让领导做判断或拍板**。受众是领导一个人，他要的是结论和决策点。

## 标准结构

```
# [事项] 进展汇报

## 结论（一句话）
现在这事到哪了，需要领导做什么。第一段就写。

## 当前进展
3-5 条，按"做了什么 → 结果"写，带数据。

## 关键问题/决策点
需要领导拍板的事：
- 选项 A：什么利弊
- 选项 B：什么利弊
- 我的建议：选哪个，为什么

## 下一步
谁、做什么、什么时候交。
```

## 分寸感

### 核心原则：带方案抛问题
不要只跟领导说"XX出问题了"。要说"XX出了问题，我建议这样处理，需要您拍板"。领导雇你是来解决问题的，不是来听问题的。

### 该做的
- **结论先行**：领导时间碎，第一段就要他知道"成了/在推进/需要你定"。
- **给选项，不要给开放式问题**："预算是批10万还是15万？"比"预算不够怎么办？"好。
- **有风险前置说**：预估到的坑，提前埋一句"这里有个风险，我们准备这样应对"。

### 不该做的
- **背景铺垫三段才进正题**：领导不关心过程，关心现在怎样、要他干嘛。
- **只报喜**：坏消息越早说越好，藏到最后炸了更麻烦。
- **过度客套**："百忙之中打扰您"这种，删掉。

## 示例

> **结论**：XX项目已完成一期，建议启动二期，需要您批二期预算15万。
>
> **进展**：一期上线两周，日活从800涨到2300，超过预期目标（1500）。
>
> **决策点**：二期有两个方向——A 做数据看板（开发2周），B 做自动审批（开发4周）。我建议先 A，因为运营现在手动导数据耗时最多。
>
> **下一步**：预算批了的话，下周一 kick-off，月底出 A 方案原型。

## 输出格式
- 发给领导私聊/邮件：完整结构，但控制在半页内
- 约会议汇报：可以把"结论"放口头，文档放细节

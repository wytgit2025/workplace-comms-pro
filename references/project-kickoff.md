# 项目启动通知指南

## 什么时候用
用户说"项目 kick-off""发个启动通知""大家对齐下""宣布开始做XX"。

受众是整个项目组和相关方，目的是让所有人知道：这事为什么做、做什么、谁负责什么、什么时候交。

## 标准结构

```
# [项目名] 启动通知

## 背景（为什么做）
一两句话说清业务问题或目标，不要长篇大论。

## 目标（做成什么样算成了）
量化目标：什么时候、达成什么指标。

## 范围
做什么、不做什么（划清边界，避免后期扯皮）。

## 分工
- PM：XXX
- 设计：XXX
- 前端：XXX
- 后端：XXX

## 关键时间点
- X月X日：需求评审
- X月X日：设计稿完成
- X月X日：开发完成
- X月X日：上线

## 协作方式
用什么工具沟通（飞书群/钉钉群）、周几同步进度。
```

## 分寸感

- **背景别写成口号**："为了提升用户体验"是空话，要写"目前XX流程需要3天，我们目标压缩到1天"。
- **不做什么要明确**：启动会上最怕后期加需求。范围里写清"本期不含XX"。
- **分工到人，不要"相关同学"**：谁负责就写谁的名字。
- **时间点要可执行**：不要"Q3完成"，要"9月30日上线"。

## 输出格式
- 发飞书文档 + 群里贴链接
- 发群里：压缩成背景一句、目标一句、分工列表、时间点表格

# 跨部门求助指南

## 什么时候用
用户说"找XX部门帮忙""跨部门协调""拉个协作""需要XX支持"。

跨部门沟通最大的坑是：你自己觉得很急，但对方不知道前因后果，凭什么帮你。所以这类沟通的核心是**给足上下文，降低对方的协作成本**。

## 标准结构

```
# 需要 [XX部门] 支持：[一句话说什么事]

## 我们在做什么
一两句话说清背景：什么项目、现在到哪了。

## 需要你们做什么
具体动作，不要模糊：
- 需要谁、做什么、产出什么、什么时候要。

## 为什么需要你们
这事和你们部门有什么关系 / 为什么找你们而不是别人。

## 时间要求
截止时间、紧急程度。如果不紧急也说清楚。

## 我们能配合什么
数据、文档、对接人，我们都准备好了。
```

## 分寸感

### 该做的
- **把上下文喂到嘴边**：不要假设对方看过你们项目文档。前因后果一段话讲清。
- **要什么写具体**："麻烦帮看下这个接口的字段定义"比"需要后端支持"好一百倍。
- **给截止时间**：没有截止时间的请求等于不会被处理。
- **降低对方成本**：相关文档链接直接贴好，不要让对方自己找。

### 不该做的
- **甩一句"在吗""方便聊下吗"**：然后等。直接说事。
- **模糊的请求**："需要你们协助一下"——协助什么？
- **不说明紧急度**：对方不知道这是今天要还是下周要，按排队处理。
- **抄送一堆领导施压**：第一次求助就抄领导，会结梁子。

## 示例

**差的写法：**
> @张三 在吗？关于那个项目，需要你们帮忙支持下。

**好的写法：**
> @张三 需要你们帮忙看下：我们在做用户中心改版，需要后端确认两个接口字段。
>
> 背景：前端开发到联调阶段，预计本周五提测。
>
> 需要：①确认 `/user/profile` 接口返回里 `roles` 字段是数组还是逗号分隔字符串；②看下 `last_login` 时区是 UTC 还是东八区。
>
> 截止：周四下班前给个回复就行，不紧急。
>
> 接口文档我贴这了：[链接]，有问题我随时在线。

## 输出格式
- 发群里 @人：用上面完整结构，但压缩成 5-8 行
- 发私聊：可以更随意，但"要什么、什么时候要"不能少

# 周报指南

## 什么时候用
用户说"写周报""这周总结""周五交周报""本周工作汇报"。

## 标准结构

不要写流水账（周一做了A、周二做了B）。按这个结构：

```
# 本周工作（X月X日—X月X日）

## 一、核心进展（2-4条，挑最重要的）
每条：做了什么 → 结果/数据 → 下周下一步

## 二、进行中的事（1-3条）
每条：进展到哪了 → 卡点是什么 → 预计什么时候出结果

## 三、问题与求助（有就写，没有就不写）
什么问题 → 需要谁支持什么

## 四、下周计划（2-4条）
下周重点要推的事
```

## 分寸感

### 该写的
- **有结果的事写结果**："完成了XX系统上线，首日1200人使用"，不是"推进了XX系统开发"。
- **卡住的事要写卡点和预期**："XX接口联调卡在对方审批，预计下周二能过"，不是"持续跟进XX"。
- **数据优先**：数字比形容词有说服力。

### 不该写的
- **流水账**：不要按天列。
- **空话**："高度重视""积极推进""持续优化""加强沟通"——这些没有信息量，删掉。
- **自我感动**：不要写"加班到很晚""付出了很多努力"，老板只看结果。
- **报喜不报忧**：有风险一定要写，提前说比事后解释好。

## 示例

**差的写法：**
> 本周主要进行了用户管理模块的开发工作，积极推进前后端联调，持续跟进测试反馈。下周将继续优化相关功能，加强团队沟通。

**好的写法：**
> 本周完成用户管理模块开发并提测，覆盖角色权限、登录态两个核心场景；当前 8 个用例通过 6 个，剩 2 个边界条件待周五修复。下周计划上线灰度，预计周三全量。

## 极简三行版（发群里/站会用）

如果只是发群里同步、或者开站会口头讲，用这个格式——30秒读完：

```
✅ 本周：[做成了什么，1句带数据]
🔜 下周：[重点推什么，1句]
⚠️ 卡点：[什么问题、需要谁支持，1句；没有就写"无"]
```

示例：
> ✅ 本周：新用户引导流程设计稿通过评审，已提测
> 🔜 下周：出灰度方案，周三前定稿
> ⚠️ 卡点：后端接口字段未对齐，预计下周二解决

**什么时候用完整版 vs 极简版：**
- 写飞书文档、发给领导正式汇报 → 完整版
- 发群里同步、开站会、口头说 → 极简三行版

## 输出格式
- 发飞书文档：用完整结构，加粗关键数据
- 发群里/站会：用极简三行版
- 发给直属领导：完整结构 + 可以口头补两句重点
